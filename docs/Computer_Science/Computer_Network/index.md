# <i class="fa-solid fa-network-wired"></i> 计算机网络
协议、公式、概念


## 1.1 初识互联网

### 网络的基本功能

1. 网络提供的最基本服务：<mark>**信息传递**</mark>
   1. 传统方式：信鸽、烽火、信使、卡车、电报、电话等
   2. 现代方式：互联网
2. 网络服务可以类比为**运输服务**：
   1. 网络传递**信息**
   2. 马车、火车、卡车和飞机传递**物体**
3. **区分不同网络**：根据网络所提供的**服务**
4. **区分不同服务**：
   1. 功能
   2. 延迟、带宽、丢失率
   3. 端节点数目、服务接口
   4. 可靠性、实时或非实时等外部特性

!!! question "思考"
    最早的信息传递方式可以追溯到人类通过**声音、动作和符号**进行直接交流，之后才出现信使、烽火等远距离传递方式。

### 多种多样的网络服务

1. **典型应用**：
   1. 远程医疗
   2. 无人码头的远程操控
   3. 矿井下网络监控与通信
   4. 星链计划 (**Starlink**)
2. **异构网络环境**：
   1. 有线或无线
   2. 通信距离远近不同
   3. 干扰情况不同
3. **业务需求各异**：对时延、带宽、可靠性、安全性和保密性的要求不同

### 网络在军事领域的应用

1. **无人机作战**：
   1. 通过卫星中继通信
   2. 要求控制链路可靠、实时、抗干扰并且保密
   3. 需要将高清视频等现场信息实时反馈
2. **其他无人设备**：无人坦克、无人舰船、无人潜艇、卫星等
3. **特殊通信方式**：
   1. 水深网络使用**声呐通信**
   2. 深空探索可以使用**激光通信**
4. 网络不仅承担通信任务，还可用于无人机的**精确制导**

### 互联网成为网络空间的核心

1. <mark>互联网是连接计算系统、应用支撑技术、行业互联网和底层通信技术的核心</mark>
2. **计算系统**：各类终端与服务器
3. **底层通信技术**：3G、4G、5G、WiFi、超高速光纤
4. **应用支撑技术**：云计算、智慧城市、三网融合、大数据、人工智能
5. **行业互联网**：物联网、金融互联网、能源互联网、工业互联网、互联网+

### 全球市值前十名公司的变迁

1. 全球高市值企业逐渐从传统工业、能源和金融企业转向**互联网与信息技术企业**
2. 苹果、谷歌、微软、亚马逊、腾讯、Facebook 等企业的市值曾突破 5000 亿美元
3. 互联网产业的发展使美国硅谷成为全球重要的科技创新中心

### 我国的新基建

1. **传统基建——“铁公基”或“铁公机”**：铁路、公路、机场等基础设施
2. **新型基础设施建设**：
   1. 5G 基站建设
   2. 特高压
   3. 城际高速铁路和城市轨道交通
   4. 新能源汽车充电桩
   5. 大数据中心
   6. 人工智能
   7. 工业互联网
3. **新基建的作用**：
   1. 作为数字经济的发展基石和转型升级的重要支撑
   2. 稳投资、扩内需、拉动经济增长
   3. 促进产业升级、优化经济结构、提高发展质量

## 1.2 网络实例

### 网络分类

1. **移动和宽带接入网络 (Mobile and Broadband Access Networks)**：用于接入互联网
2. **数据中心网络 (Data-center Networks)**：承载数据和应用
3. **传输网络 (Transit Networks)**：连接接入网络与数据中心
4. **企业网络 (Enterprise Networks)**：用于校园、办公楼和其他组织内部

### 按地域规模分类

1. **个域网 (PAN, Personal Area Network)**：
   1. 便携式消费电子与通信设备之间的短距离通信网络
   2. 覆盖范围通常在半径 10 米以内
   3. **e.g.** 蓝牙耳机
2. **局域网 (LAN, Local Area Network)**：
   1. 在局部地区形成的区域网络
   2. 范围可以是一栋建筑，也可以是一个办公室
   3. **e.g.** 电脑通过 WLAN 接入、共享打印机
3. **城域网 (MAN, Metropolitan Area Network)**：覆盖一座城市
4. **广域网 (WAN, Wide Area Network)**：覆盖很大的地理区域，甚至多个地区或国家

### Internet 与 internet

1. **相同点**：二者都是“网络的网络”
2. **互联网 (Internet)**：
   1. 一个特定的互连网，是专有名词
   2. 遵循 **TCP/IP** 标准
   3. 利用路由器将各种计算机网络互连，覆盖全球
3. **互连网 (internet)**：
   1. 泛指多个不同类型计算机网络互连形成的网络，是普通名词
   2. 除 TCP/IP 外，也可以采用其他协议

!!! warning "注意"
    <mark>首字母大写的 `Internet` 特指全球互联网；小写的 `internet` 泛指互连网。</mark>

### ARPANET

1. **ARPANET** 是现代互联网的重要前身
2. 其节点数量不断增长：1969 年 12 月只有少量节点，1972 年已扩展到更多高校和研究机构
3. ARPANET 的软件最初分为两个部分：
   1. **子网软件**：由 IMP 以及 IMP 之间的协议组成
   2. **主机软件**：由 Host-IMP 协议和 Host-Host 协议组成
4. 后来在主机中加入**源 IMP 到目的 IMP 协议**，提高可靠性

### 互联网的层级结构

1. **Tier-1 ISP**：全球最高级别 ISP，彼此相连
   1. **e.g.** AT&T、Verizon、NTT、Sprint、British Telecom、Deutsche Telekom
2. **Tier-2 ISP**：教育网、地区 ISP 等，通常需要向更高级 ISP 购买流量
3. **本地 ISP**：直接为校园、公司、家庭等终端用户提供接入
4. **IXP (Internet Exchange Point)**：互联网交换点，使不同 ISP 可以直接交换流量
5. <mark>现实互联网具有复杂的层级结构，但并不是严格的树形结构</mark>

### 互联网的构成

1. **网络边缘 (Network Edge)**：
   1. 由与互联网相连的计算机和其他设备组成
   2. 这些设备称为**端系统 (End System)**
   3. 端系统也称为**主机 (Host)**
2. **网络核心 (Network Core)**：
   1. 由互连端系统的分组交换设备和通信链路构成
   2. 主要设备是**路由器**和**交换机**
   3. 通信链路可以是光纤、铜缆、无线电或卫星链路

### 网络边缘与主机

1. **客户端主机**：便携机、智能手机、平板电脑、智能手环等
2. **服务器主机**：通常位于数据中心
3. **主机的功能**：
   1. 运行应用程序
   2. 产生信息并向网络发送数据
   3. 从网络接收数据并提供给应用程序

### 接入网概述

1. **接入网的目标**：<mark>将端系统连接到边缘路由器</mark>
2. **边缘路由器**：端系统到其他远程端系统路径上的第一台路由器
3. **有线接入技术**：光纤到户 FTTH、以太网、同轴电缆、数字用户线 DSL
4. **无线接入技术**：WiFi、4G、5G、卫星广域覆盖
5. **接入场景**：住宅、机构、移动网络等

### 光纤到户 FTTH

1. **FTTH (Fiber To The Home)**：光纤直接连接到用户家庭
2. 常采用**无源光网络 (PON, Passive Optical Network)**：
   1. **OLT (Optical Line Terminal)**：局端设备
   2. **ONU (Optical Network Unit)**：用户侧光网络单元
   3. 光纤分配网中使用无源分光器连接多个 ONU
3. **特点**：带宽高、线路稳定

### 数字用户线 DSL

1. **DSL (Digital Subscriber Line)**：复用电话线连接到数字用户线接入复用器 **DSLAM**
2. **DSLAM** 将用户的数据接入互联网，并将语音接入电话网
3. 语音和数据可以在不同频率上同时传输
4. DSL 的上下行速率通常**不对称**，下行速率高于上行速率

### 同轴电缆接入

1. 家庭使用传统有线电视信号线接入互联网
2. 多个家庭共享有线电视的头端设备
3. **混合光纤同轴电缆 (HFC)**：
   1. 先由同轴电缆汇聚到光纤节点
   2. 再通过光纤连接到头端
4. 多用户共享链路带宽，可能相互影响

### 无线接入

1. 无线接入网通过基站或**接入点 (Access Point)** 将端系统连接到边缘路由器
2. **无线局域网 (WLAN)**：
   1. 通常在建筑物内使用，覆盖约几十米
   2. 典型标准为 IEEE 802.11，即 WiFi
3. **广域蜂窝接入网**：
   1. 由移动网络运营商提供，覆盖可达数千米
   2. **e.g.** 2G、3G、4G、5G

### 企业和家庭网络

1. 实际接入网通常混合使用有线和无线技术
2. **有线接入**：100 Mbps、1 Gbps、10 Gbps 等
3. **无线接入**：WiFi 等
4. 家用路由器常同时集成：
   1. 路由器
   2. 交换机
   3. 无线接入点
   4. NAT

### 物理介质

1. **传输单元**：位 (**bit**)
2. **物理介质**：发送机和接收机之间用于传播信号的具体媒介
3. **引导型介质 (Guided Media)**：信号在固体介质中传播
   1. 铜线
   2. 光纤
   3. 同轴电缆
4. **非引导型介质 (Unguided Media)**：信号自由传播
   1. 无线电
   2. 卫星无线电信道

!!! warning "单位"
    1. 网络传输常用 `bit`；存储常用字节 `Byte`
    2. <mark>**1 B = 8 b**</mark>，大小写不能混淆
    3. 传输速率中的 K/M/G 通常按 $10^3$ 进位；存储容量常按 $2^{10}$ 进位

#### 光纤

1. 通过玻璃纤维中的光脉冲传输，每个脉冲表示一个位
2. 支持高速点到点传输，可达到 10～100 Gbps 甚至更高
3. 误码率低
4. 中继器之间距离远，对电磁噪声免疫

#### 双绞线与同轴电缆

1. **双绞线 (Twisted Pair)**：
   1. 两根绝缘铜线互相缠绕
   2. 电话线通常使用一对双绞线
   3. 网线通常含 4 对双绞线，广泛用于计算机网络
2. **同轴电缆**：
   1. 两根同心铜导线，可双向传输
   2. 常用于电缆上的多个频率通道

#### 无线介质

1. 通过电磁频谱中的电磁波传递信号，不依赖物理线路
2. 通常采用半双工方式，同一时刻只能向一个方向发送
3. 传播环境会受到反射、物体阻挡和干扰/噪声影响
4. **类型**：
   1. 无线局域网 WiFi
   2. 广域蜂窝网络
   3. 蓝牙
   4. 地面微波
   5. 卫星通信

### 网络核心

1. **目标**：将海量端系统连接起来
2. 网络核心由各种交换机、路由器和链路构成，形成**网状网络**
3. 网络核心采用**分组交换**，包含两项基本功能：
   1. **路由 (Routing)**：确定分组从源主机到目的主机所经过的路径
   2. **转发 (Forwarding)**：在路由器内部将到达输入端口的分组送到正确输出端口

!!! info "全局与本地"
    1. 路由是**全局操作**，通过路由协议和路由算法生成路由表
    2. 转发是**本地操作**，根据分组首部和转发表选择输出端口

### 电路交换

1. **电路交换 (Circuit Switching)**：通信前先建立连接，并为连接预留专用资源
2. 预留资源包括链路带宽资源和交换机的交换能力
3. **特点**：
   1. 通信双方建立一条物理或逻辑通路
   2. 资源专用，即使空闲也不能被其他连接共享
   3. 性能稳定，但连接建立需要时间
   4. 某段链路故障时，通信可能中断
4. **多路复用**：
   1. **频分多路复用 (FDM)**：不同连接占用不同频带
   2. **时分多路复用 (TDM)**：不同连接轮流占用不同时隙

!!! warning "局限"
    电路交换难以适应互联网中具有突发性 (**Burst**) 的流量，因为预留资源在空闲期间仍不能被其他用户利用。

### 存储转发

1. **存储转发 (Store-and-Forward)**：路由器必须收到一个分组的全部数据后，才能向下一跳发送
2. 长度为 $L$ bit 的分组，在速率为 $R$ bit/s 的链路上的传输时延：

$$
d_{trans}=\frac{L}{R}
$$

3. 如果分组经过多条速率相同且忽略其他时延的链路，总传输时延等于各段传输时延之和

### 分组交换

1. **分组交换 (Packet Switching)**：
   1. 将大报文分成较小的**分组**
   2. 使用存储转发方式逐跳发送
   3. 每个分组携带源地址和目的地址等控制信息
   4. 路由器根据分组信息逐跳选择传输路径
2. 多个用户共享链路带宽，称为**统计多路复用 (Statistical Multiplexing)**
3. 不同分组可以经过不同路径到达目的地
4. **优点**：资源利用率高，适合具有大量突发数据传输需求的互联网
5. **代价**：可能产生排队、时延抖动和丢包

### 三种交换方式的比较

1. **电路交换**：
   1. 先建立连接并预留资源
   2. 性能稳定
   3. 灵活复用困难，链路利用率可能较低
2. **报文交换**：
   1. 以完整报文为交换单位
   2. 需要存储整个报文，对缓存要求高
   3. 报文较长时会长时间占用链路
3. **分组交换**：
   1. 将报文划分为多个分组
   2. 存储和传输更灵活
   3. 能进行统计复用，提高网络利用率

<mark>分组交换适合具有大量突发数据传输需求的互联网。</mark>

## 1.3 协议与分层结构

### 协议设计目的

1. 人之间顺利交流需要：共同语言、相互理解、共同语义
2. 计算机之间也必须约定通信过程，才能理解彼此发送的信息
3. **网络协议 (Network Protocol)**：为网络中的数据交换而建立的规则、标准或约定
4. 网络协议的三个要素：
   1. **语法 (Syntax)**：规定传输数据的格式，即“如何讲”
   2. **语义 (Semantics)**：规定需要完成的功能，即“讲什么”
   3. **时序 (Timing)**：规定各种操作的顺序以及“何时讲”
5. **协议设计需要解决的问题**：
   1. 可靠性
   2. 资源分配
   3. 拥塞问题
   4. 自适应性
   5. 安全问题

### 分层结构的必要性

1. 计算机网络复杂且异构：
   1. 介质不同：光纤、铜线、空气等
   2. 接入方式不同：有线、WLAN、移动数据网络、蓝牙等
   3. 应用类型不同：无人驾驶、万物互联、短视频、邮件等
   4. 高速更新迭代：3G、4G、5G 等
2. **分层结构的作用**：
   1. 明确和简化每一层的功能
   2. 各层独立，便于技术演进
   3. 统一标准，保证不同技术之间能够互操作 (**Interoperable**)
   4. 以模块化方式降低系统复杂度

### 分层结构示例

1. **层级组织——分层**：总裁 → 总监 → 经理 → 程序员
2. **内部独立——模块**：不同成员可以使用不同工具，但只要输出满足约定即可协作
3. **沟通协作——标准**：合作协议、项目文档、接口定义等
4. **邮政系统类比**：
   1. 用户应用层：用户书写和读取信件
   2. 信件递送层：邮局处理邮件
   3. 交通运输层：铁路、汽车等运送货物
   4. 同层实体按共同规则工作，上下层通过接口协作

### 协议分层结构

1. **层次栈 (A Stack of Layers)**：网络协议按功能组织成多个层次
2. **对等实体 (Peers)**：不同机器上组成相同层次的实体
3. **接口 (Interface)**：相邻层之间的边界，定义下层向上层提供的服务原语
4. **网络体系结构 (Network Architecture)**：网络层次以及各层协议的集合
5. **协议栈 (Protocol Stack)**：一个特定系统采用的一组协议

!!! info "逻辑通信与实际通信"
    1. 对等实体之间进行的是**逻辑通信**
    2. 实际数据沿发送端协议栈向下传递，经物理介质传输后，再沿接收端协议栈向上交付

### 封装与解封装

1. **发送端**：层层封装 (**Encapsulation**)
2. **接收端**：层层解封装 (**De-encapsulation**)
3. 上层数据向下传递时，每一层加入本层的控制信息；接收端对应层再移除这些信息
4. 不同层对应的协议数据单元称为 **PDU (Protocol Data Unit)**

```text
发送端：应用数据 → 加入各层首部 → 比特流
接收端：比特流 → 移除各层首部 → 应用数据
```

### 服务原语

1. **面向连接服务 (Connection-oriented Service)**：类比电话系统
   1. 先建立连接
   2. 再进行数据传输
   3. 最后释放连接
   4. 一个请求或响应之后，对方通常会产生后续动作
2. **无连接服务 (Connectionless Service)**：类比邮政系统
   1. 每个消息独立发送
   2. 消息需要携带完整的目的地址
   3. 传输过程中不要求对方逐次应答
3. **服务**：
   1. 典型服务包括面向连接服务和无连接传输服务
   2. 服务由一组供用户调用的原语或操作定义
   3. 服务规定相邻两层之间能够执行的操作
4. 以面向连接服务为例，核心原语通常包括：连接请求、接受响应、请求数据、应答、请求断开和断开连接

### 服务与协议的关系

1. <mark>**协议是“水平的”，服务是“垂直的”**</mark>
2. **协议**：同层对等实体之间通信所遵循的规则
3. **服务**：下层实体通过接口向上层实体提供的能力
4. 实体使用协议实现本层定义的服务，并使用下一层提供的服务

!!! question "思考题"
    **A protocol is an agreement between the ______ on how communication is to proceed.**

    答案：**peers on different nodes**，即不同节点上的对等实体。

## 1.4 参考模型

### OSI 参考模型

1. **OSI (Open Systems Interconnection)**：开放系统互连参考模型
2. 由 Day 和 Zimmermann 于 1983 年提出
3. OSI 将网络通信划分为 7 层：

```text
应用层 → 表示层 → 会话层 → 传输层 → 网络层 → 数据链路层 → 物理层
```

#### 物理层

1. 定义如何在信道上传输 `0` 和 `1`，即 **Bits on the wire**
2. 关注内容：
   1. **机械特性 (Mechanical)**：接口大小、形状、线缆排列
   2. **电气特性 (Electrical)**：电压、电流等
   3. **时序接口 (Timing)**：采样频率、波特率、比特率等
   4. **介质 (Medium)**：双绞线、光纤、无线信道等

#### 数据链路层

1. 实现相邻 (**Neighboring**) 网络实体之间的数据传输
2. **成帧 (Framing)**：从物理层比特流中提取完整的帧
3. **错误检测与纠正**：提高可靠数据通信能力
4. **物理地址**：使用 MAC 地址标识设备
5. **流量控制**：避免发送端过快导致接收端缓冲区溢出
6. **共享信道访问控制 (MAC)**：协调多个节点对同一介质的使用

#### 网络层

1. 将数据包跨越网络从源设备传递到目的设备，实现 **Host to Host** 通信
2. **路由 (Routing)**：在网络中选择从源到目的的转发路径
3. **路由协议**：路由器之间交流路由信息的协议规范
4. **服务质量 (QoS) 控制**：可能涉及拥塞、负载均衡、准入控制和保证时延等
5. 负责异构网络之间的互联与分组转发

!!! question "为什么有 MAC 地址还需要 IP 地址？"
    1. MAC 地址主要用于**同一链路或局域网内**的帧传输
    2. IP 地址具有层次化结构，用于在不同网络之间进行**路由选择**
    3. 因此，跨网络通信不能只依赖 MAC 地址

#### 传输层

1. 将数据从源端口发送到目的端口，实现**进程到进程**的通信
2. 网络层定位到一台主机，传输层进一步定位到主机上的某个进程
3. 传输层为终端用户提供端到端的数据传输控制
4. **两类模式**：
   1. **可靠传输**：保证数据准确、有序到达，适合文件传输等
   2. **不可靠传输**：更快捷，适合实时语音和视频等允许少量丢失的应用

#### 会话层、表示层与应用层

1. **会话层 (Session Layer)**：利用传输层服务，在应用程序之间建立和维持会话，并控制会话过程
2. **表示层 (Presentation Layer)**：处理信息的语法和语义，管理数据表示方法和传输格式转换
3. **应用层 (Application Layer)**：通过应用层协议向应用程序提供网络服务调用

### TCP/IP 参考模型

1. TCP/IP 参考模型源于 ARPANET，最初并没有精确定义独立模型
2. **链路层 (Link Layer)**：描述链路必须具备的功能，以满足无连接互联网层的需求
3. **互联网层 (Internet Layer)**：
   1. 允许主机将数据包注入网络
   2. 数据包独立传输至目的地
   3. 数据包可以按不同路径传输，并可能乱序到达
4. **传输层 (Transport Layer)**：允许源主机与目的主机中的对等实体进行端到端数据传输
   1. TCP
   2. UDP
5. **应用层 (Application Layer)**：包含 DNS、HTTP、FTP、SMTP 等高层协议

### TCP/IP 的设计思想

1. 源于“笨终端、聪明网络”的电信系统设计思想
2. 互联网采用<mark>**网络简单、终端复杂**</mark>的设计：
   1. 网络尽力传输数据
   2. 可靠性、丢失恢复等功能主要由终端完成
3. **IP 分组交换的特点**：
   1. IP 可以运行在各种底层物理网络之上，即 **IP over Everything**
   2. 各类应用也可以运行在 IP 之上，即 **Everything over IP**
   3. 每个 IP 分组携带目的地址
   4. 网络核心通过路由和转发实现通信，适应性强

### OSI 与 TCP/IP 模型比较

1. **层数**：
   1. OSI：7 层
   2. TCP/IP：常划分为 4 层或 5 层
2. **层次对应关系**：
   1. OSI 的应用层、表示层、会话层 → TCP/IP 应用层
   2. OSI 传输层 → TCP/IP 传输层
   3. OSI 网络层 → TCP/IP 互联网层
   4. OSI 数据链路层、物理层 → TCP/IP 网络接口层
3. **基本思想**：
   1. OSI 先定义通用模型，再制定协议，接口、协议和服务概念清晰
   2. TCP/IP 先有协议，模型是对已有协议的描述，更注重实用性
4. **连接服务**：
   1. OSI 网络层同时支持面向连接和无连接通信
   2. TCP/IP 互联网层只提供无连接通信

### 两种模型的不足

1. **OSI 模型的不足**：
   1. 提出的时机较晚，已有厂商支持其他协议
   2. 技术实现复杂，部分层次的功能划分不均衡
   3. 实现效率不高
   4. TCP/IP 已成为 UNIX 的一部分并免费使用
   5. 被认为是政府机构强制推动的标准
2. **TCP/IP 模型的不足**：
   1. 核心概念未能清晰区分服务、接口和协议
   2. 不够通用，不适合描述 TCP/IP 之外的协议栈
   3. 链路层与物理层常被合并为网络接口层，划分不够清晰
   4. 模型完整性相对较差

### 本课程使用的五层模型

1. 为突出核心概念并兼顾完整性，本课程采用五层结构：

```text
应用层 → 传输层 → 网络层 → 链路层 → 物理层
```

2. 这种划分兼顾：
   1. 简化分层，便于教学
   2. 保留物理层和数据链路层的区别
   3. 与互联网实际协议体系相对应
3. 各层 PDU 名称：
   1. 应用层：消息 (**Message**)
   2. 传输层：段 (**Segment**)
   3. 网络层：数据报或分组 (**Datagram/Packet**)
   4. 链路层：帧 (**Frame**)
   5. 物理层：比特 (**Bit**)

!!! success "核心映射"
    ```text
    端到端通信：主机 A 的应用 → 主机 B 的应用
    中间交换机：主要处理链路层和物理层
    路由器：主要处理网络层、链路层和物理层
    ```

## 1.5 计算机网络度量单位

### 比特率、带宽与包转发率

1. **比特率 (Bit Rate)**：主机在数字信道上传送数据的速率，也称数据率
   1. 单位为 bit/s 或 b/s
   2. 常用单位：Kbit/s、Mbit/s、Gbit/s
2. **带宽 (Bandwidth)**：
   1. 网络中某信道能够传送数据的能力
   2. 表示单位时间内网络信道能够通过的最高数据率
   3. 单位通常为 bit/s
3. **包转发率 (PPS, Packet Per Second)**：
   1. 表示交换机或路由器每秒能够转发的分组数量
   2. 常用于评价交换机端口满负载时的转发能力

### 时延

1. **时延 (Delay/Latency)**：数据从网络或链路的一端传送到另一端所需要的时间
2. **四种主要时延**：
   1. **传输时延 (Transmission Delay)**：数据从节点进入传输媒体所需的时间
   2. **传播时延 (Propagation Delay)**：电磁波在信道中传播一定距离所需的时间
   3. **处理时延 (Processing Delay)**：主机或路由器处理分组所花费的时间
   4. **排队时延 (Queueing Delay)**：分组在输入或输出队列中等待处理所花费的时间
3. 传输时延：

$$
d_{trans}=\frac{\text{Length (bit)}}{R\ (\text{bit/s})}
$$

4. 传播时延：

$$
d_{prop}=\frac{\text{Distance (m)}}{c\ (\text{m/s})}
$$

5. 节点总时延：

$$
d_{total}=d_{proc}+d_{queue}+d_{trans}+d_{prop}
$$

!!! warning "传输时延与传播时延"
    1. **传输时延**取决于分组长度 $L$ 和链路速率 $R$
    2. **传播时延**取决于链路距离和信号传播速度
    3. 二者是不同概念，不能混为一谈

### 往返时延 RTT

1. **RTT (Round-Trip Time)**：从发送方开始发送数据，到发送方收到接收方确认所经历的总时间
2. RTT 可以用于判断网络连通性和测量网络时延
3. `ping` 命令可以测量往返时延

### 时延带宽积

1. **时延带宽积**：传播时延与带宽的乘积

$$
\text{时延带宽积}=\text{传播时延}\times\text{带宽}
$$

2. 其物理意义是：<mark>链路中能够同时存在的比特数量</mark>
3. 如果发送端连续发送数据，当第一个比特到达终点时，发送端已经发送的比特数量就是时延带宽积
4. 可以将链路理解为一条有“长度”和“容量”的管道

!!! example "计算"
    若传播时延为 $20\text{ ms}$，带宽为 $10\text{ Mb/s}$：

    $$
    20\times10^{-3}\times10\times10^6=2\times10^5\text{ bit}
    $$

### 吞吐量、有效吞吐量与利用率

1. **吞吐量 (Throughput)**：单位时间内通过某个网络、信道或接口的数据量，单位通常为 bit/s
2. **有效吞吐量 (Goodput)**：单位时间内目的地正确接收到的**有效信息**数量
3. **利用率**：
   1. 信道利用率：信道有百分之多少的时间处于使用状态
   2. 网络利用率：全网络信道利用率的加权平均值
4. 瓶颈链路决定端到端吞吐量：

$$
\text{Throughput}\approx \min(R_1,R_2,\ldots,R_n)
$$

### 丢包率与时延抖动

1. **丢包率**：丢失数据包数量占所发送数据包数量的比例
2. **时延抖动 (Jitter)**：时延随时间发生变化
   1. 常由网络队列和缓存中的等待变化造成
   2. 对语音、视频等多媒体业务影响明显
3. **延迟丢包**：多媒体应用到达时间过晚的数据包即使最终收到，也可能因失去使用价值而被视为丢失

## 1.6 网络安全与威胁

### 网络安全问题的由来

1. 互联网最初主要连接一组相互信任的用户，设计时没有充分考虑安全性
2. 网络空间已成为继陆、海、空、天之后的重要空间
3. 当前网络安全需要回答：
   1. 如何攻击计算机网络
   2. 如何防御网络攻击
   3. 如何设计能够抵御攻击的体系结构

<mark>没有网络安全，就没有国家安全。</mark>

### 网络安全案例与三要素

1. **Mythos**：具有强大的网络攻击能力，可自主挖掘操作系统和浏览器的 0-day 漏洞
2. **0-day 漏洞**：尚未被厂商公开修补或防御的漏洞
3. **供应链攻击**：在软件、模型或依赖发布和分发环节植入恶意内容
4. **网络安全三要素 CIA**：
   1. **机密性 (Confidentiality)**：信息不被未授权者获取
   2. **完整性 (Integrity)**：信息不被未授权篡改
   3. **可用性 (Availability)**：授权用户能够正常使用系统和服务

### 后门程序与网络监听

1. **后门程序 (Backdoor)**：绕过正常安全控制，秘密获取程序或系统访问权的方法
2. **网络监听 (Sniffing)**：监视网络状态和数据流量，截获网络上传输的信息
3. “棱镜门”事件表明，大规模监听可能造成全球性的信息安全与隐私风险

### 恶意软件

1. **恶意软件 (Malware)**：为了获取利益或实施破坏而设计的软件
   1. 删除或破坏文件
   2. 安装间谍软件收集隐私
   3. 控制受感染设备继续攻击其他设备
2. **自我复制**：恶意软件感染一台主机后，继续寻找并感染更多主机
3. **病毒 (Virus)**：
   1. 通常需要用户交互才能传播
   2. **e.g.** 打开恶意邮件附件后执行并传播
4. **蠕虫 (Worm)**：
   1. 无需用户明显交互即可运行和传播
   2. 通过不断扫描网络中的漏洞主机进行扩散
5. **勒索软件 (Ransomware)**：加密用户文件并索要赎金
   1. **e.g.** WannaCry

### 拒绝服务攻击

1. **拒绝服务攻击 (DoS, Denial-of-Service)**：通过制造大量虚假流量占用资源，使合法用户无法使用资源或服务
2. 一般过程：
   1. 选择攻击目标
   2. 入侵并控制大量主机，形成**僵尸网络**
   3. 从被控制主机向目标发送大量数据包
   4. 目标因资源耗尽而无法响应正常请求
3. **僵尸网络 (Botnet)**：由攻击者控制的大量感染设备组成的一对多控制网络
4. **DDoS**：利用多个分布式攻击源同时发动拒绝服务攻击

### 网络安全防御

1. **身份认证**：证明通信方“确实是其声称的身份”
2. **保密**：使用加密技术防止信息泄露
3. **完整性检查**：使用数字签名、消息认证码等检测篡改
4. **访问限制**：使用密码保护的 VPN、访问控制等限制资源访问
5. **防火墙**：部署在接入网络与核心网络之间，过滤和控制网络流量

### 我国网络安全相关法规

1. 《中华人民共和国网络安全法》：2016 年 11 月 7 日发布
2. 《互联网信息服务管理办法》：2000 年 9 月 25 日公布施行
3. 相关法规会随网络发展持续修订和完善

## 1.7 标准化组织

### 国际标准组织

1. **ISO (International Organization for Standardization)**：
   1. 国际标准化组织
   2. 包括许多国家的标准团体
   3. ISO 7498 定义了 OSI 七层参考模型
2. **ITU (International Telecommunication Union)**：
   1. 国际电信联盟，其前身是国际电报电话咨询委员会 CCITT
   2. 由 ITU-R、ITU-D 和 ITU-T 三个部门组成
   3. 制定网络和电话通信领域的标准
   4. 采用政府代表和工业组织代表参与的形式

### IEEE、WiFi 联盟与 W3C

1. **IEEE (Institute of Electrical and Electronics Engineers)**：
   1. 世界上重要的专业技术团体
   2. IEEE 802 委员会制定 802 局域网标准
   3. **e.g.** IEEE 802.3、IEEE 802.11
2. **WiFi 联盟 (WiFi Alliance/WFA)**：
   1. 企业联盟
   2. 负责 WiFi 相关认证和互操作性推广
   3. 发展 IEEE 802.11 标准定义的无线局域网技术
3. **万维网联盟 (W3C, World Wide Web Consortium)**：
   1. 制定 Web 标准的非营利组织
   2. 标准涉及结构、表现和行为
   3. **e.g.** XML、XHTML、CSS、DOM、ECMAScript

### IETF 与 IRTF

1. **IETF (Internet Engineering Task Force)**：互联网工程任务组
   1. 国际民间组织
   2. 制定互联网协议标准的核心组织
   3. TCP、IP、HTTP 等标准均由 IETF 推动制定
   4. 划分为互联网、路由、传输、安全、应用、运行管理等领域
   5. 具体工作由超过 100 个工作组 **WG (Working Group)** 承担
2. **IRTF (Internet Research Task Force)**：互联网研究任务组
   1. 下设多个研究组，研究特定协议、应用和体系结构
   2. 通常发布研究报告，但不直接制定协议标准
3. **典型 RFC**：
   1. RFC 793：TCP
   2. RFC 791：IP

### RFC 与 IETF 参与方式

1. 互联网标准以 **RFC (Request for Comments)** 文档形式公开
2. RFC 文档可以免费获取
3. IETF 自身的规章制度和 RFC 产生规则也通过 RFC 发布
4. IETF 每年举行多次会议，但决策必须在邮件列表中确认，因此可以远程参与
5. IETF 没有会员制，任何人都可以通过邮件列表参与

!!! quote "IETF 名言"
    **We reject: kings, presidents, and voting. We believe in: rough consensus and running code.**

    我们拒绝国王、总统和投票；我们信仰大致共识和可运行的代码。

### RFC 产生过程

1. 个人提交草案
2. 在邮件列表讨论或参加会议
3. 工作组接受草案，使其成为工作组文稿
4. 工作组讨论并进行 **Working Group Last Call**
5. 进行 **IETF Last Call**
6. 由 **IESG** 审核
7. 审核通过后发布为 RFC
8. 整个过程通常至少需要 2～3 年

```text
个人文稿 → 工作组接受 → 工作组文稿 → WG Last Call
        → IETF Last Call → IESG 审核 → RFC
```

### Internet 标准化组织结构

1. **ISOC (Internet Society)**：互联网协会，为 IETF 等组织提供法律支撑
2. **IAB (Internet Architecture Board)**：互联网体系结构委员会
   1. IETF 的顶层架构委员会
   2. 负责指导 TCP/IP 协议族的开发和研究方向
3. **IETF** 由互联网工程指导小组 **IESG** 指导，下设多个领域和工作组 WG
4. **IRTF** 由互联网研究指导小组 **IRSG** 指导，下设多个研究组 RG

```text
ISOC
└── IAB
    ├── IRTF → IRSG → RG
    └── IETF → IESG → Area → WG
```

### 中国通信标准化协会 CCSA

1. **CCSA (China Communications Standards Association)**：中国通信标准化协会
2. 成立于 2002 年 12 月 18 日

## 1.8 互联网发展史与启示

### 互联网早期发展

1. **1957 年 10 月**：苏联成功发射第一颗人造卫星“斯普特尼克 1 号”
2. **1958 年 2 月**：美国成立国防高级研究计划局 ARPA
3. **1969 年**：ARPANET 诞生，创新采用分组交换技术，最初连接 UCLA、SRI、UCSB 和 Utah 四个节点
4. **1972 年底**：ARPANET 已扩展到 24 个站点
5. **1983 年**：ARPANET 采用 TCP/IP，也被视为互联网诞生的重要标志
6. **1990 年**：ARPANET 退役，相关网络工作转向 NSF 等机构
7. 到 20 世纪 80 年代中期，Internet 已横跨北美、欧洲和澳大利亚，成为全球性网络

!!! info "互联网诞生的两种说法"
    1. 1969 年 ARPANET 诞生
    2. 1983 年 ARPANET 正式采用 TCP/IP

### ARPANET 胜出的原因

1. 互联网早期曾出现多个网络项目：
   1. 美国：ARPANET、NSFNET
   2. 英国：NPL Mark I
   3. 法国：CYCLADES
   4. 欧洲：WWW、Linux 等相关技术
   5. 苏联：“红书”方案、OGAS
2. 美国发起的 ARPANET 最终成为现代互联网的基础
3. 重要条件：
   1. 具有挑战传统的创新思想
   2. 军事战略需求明确
   3. 政府持续投入充足经费
   4. 市场经济推动商业化
   5. 汇聚高水平研究团队
   6. TCP/IP 与 WWW 等关键技术持续成熟

### 互联网早期发展的启示

1. **诞生阶段**：
   1. 具有传统技术无法解决的重大战略需求
   2. 分组交换理论突破与原型系统实验并举
   3. 从 1969 年开始得到政府长期支持
2. **成长壮大阶段**：
   1. 采用简单、实用的 TCP/IP 技术路线
   2. 以教育和科研示范网络为起点
   3. 通过 IETF/RFC 进行开放式联合研究
   4. 在持续试错中快速发展

### 互联网的新发展

1. **Web 1.0（1993～1999）**：
   1. 1993 年 Mosaic 浏览器诞生，推动互联网商用
   2. 1994 年 W3C 成立
   3. 浏览器、门户网站、电子商务兴起
   4. 典型接入：ISDN，约 64 Kbps
2. **Web 2.0（2000～2007）**：
   1. 2000 年互联网泡沫破灭，行业进入调整期
   2. 博客、社交媒体和在线视频发展
   3. 典型接入：DSL/LAN，约 10 Mbps
3. **移动互联网（约 2007～2018）**：
   1. 2007 年 3G 与 iPhone 推动移动互联网
   2. 2010 年 4G LTE 开始部署
   3. 导航、网购、互联网+等应用迅速发展
   4. 典型接入：WiFi + 4G，约 100 Mbps
4. **智能互联阶段**：
   1. IoT、车联网、5G+进入各行业
   2. 网络向万物互联和一体化方向发展

### 技术与商业发展的启示

1. <mark>商业需求是核心驱动力，技术创新提供重要基础</mark>
2. 企业的长期参与和投入推动互联网基础设施发展
3. 有线 → 无线 → 广覆盖，接入便捷程度影响用户使用方式和在线时间
4. 网络性能决定应用体验，是互联网应用发展的必要条件
5. 网络带宽决定可以承载的信息类型：

```text
文本 → 图片（静态 → 动态）→ 音频 → 视频（低清 → 高清，短视频 → 直播）
```

6. 早期互联网数据以下行为主，对下行带宽要求高；直播等应用使用户开始大量产生数据，对上行带宽提出更高要求
7. 网络性能提升和延迟降低，也会推动计算、存储和传输之间的重新分工

### 我国互联网发展情况

1. **起步阶段**：
   1. 1987 年建成第一个电子邮件节点，从北京向德国成功发送邮件
   2. 1994 年我国通过 64 Kbit/s 专线接入互联网，实现全功能连接
2. **主要骨干网络**：
   1. CHINANET：中国电信
   2. UNINET：中国联通
   3. CMNET：中国移动
   4. CERNET：中国教育和科研计算机网
   5. CSTNET：中国科技网
3. 我国在国际出口带宽、移动通信基站、IP 地址、域名和应用数量等方面快速发展

### 下一代互联网与宽带中国

1. **CNGI (China's Next Generation Internet)**：中国下一代互联网示范工程
2. CNGI-CERNET2：大型纯 IPv6 互联网主干网
3. **“宽带中国”战略**：
   1. 全面提速（2013 年）
   2. 推广普及（2014～2015 年）
   3. 优化升级（2016～2020 年）
4. 接入技术演进：

```text
拨号上网 → 双绞线上网 → 光纤入户
```

5. 移动通信牌照：
   1. 2009 年发放 3G 牌照
   2. 2013 年发放 4G 牌照
   3. 2019 年发放 5G 商用牌照

!!! question "NGN 与 NGI"
    1. **NGN (Next-generation Network)**：下一代网络，强调电信网络整体演进
    2. **NGI (Next-generation Internet)**：下一代互联网，强调互联网体系结构和协议演进

### 中国教育和科研计算机网 CERNET

1. 始建于 1994 年，是重要的学术互联网，由教育部管理，多所高校承担建设和运行
2. 国家网络中心设在清华大学
3. 网络按国家中心、地区中心、省级节点和接入学校进行组织
4. **自治系统号**：AS 4538
5. **网络结构**：
   1. 地区中心之间使用 iBGP 互连
   2. 地区中心通过 eBGP 与外部互联单位连接
   3. 下层连接省级节点、接入用户和学校

```text
国家网络中心
    ↓
八大地区中心（iBGP 全连接）
    ↓
地区级/省级节点
    ↓
接入学校、用户与互联单位
```

   2. 重视专利质量
   3. 积极参与 3GPP、ITU-T、IETF 等标准组织

## 本章总结

1. 计算机网络的最基本功能是**信息传递**，不同应用对带宽、时延、可靠性和安全性的需求不同
2. 网络由**网络边缘、接入网和网络核心**组成
3. 网络核心采用**路由和转发**，分组交换适合互联网中的突发流量
4. **协议**规定对等实体之间通信的规则，三要素是语法、语义和时序
5. 分层结构通过服务、接口和协议降低复杂度：
   1. 服务是垂直的
   2. 协议是水平的
6. 参考模型包括理想化的 **OSI 七层模型**和现实使用的 **TCP/IP 模型**
7. 本课程采用五层结构：应用层、传输层、网络层、链路层和物理层
8. 网络的主要度量包括带宽、时延、吞吐量、丢包率、利用率和时延抖动
9. 网络威胁无处不在，安全的核心目标是机密性、完整性和可用性
10. 主要标准组织包括 ITU、ISO、IEEE、IETF、IRTF、W3C 和 CCSA
11. 互联网的发展说明：<mark>重大需求、技术创新、开放协作、持续投入和商业驱动共同决定网络技术的演进</mark>

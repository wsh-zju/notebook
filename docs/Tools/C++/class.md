# 类

??? example "Example"
    ```cpp
    #include <iostream>

    class point {
    public:
        // 成员函数声明
        void init(int x, int y);
        void move(int dx, int dy);
        void print() const; 

    private:        // 外部无法访问
        int x, y;
    };

    // --- 成员函数的实现 ---

    void point::init(int x, int y) {
        this->x = x;        // this 指向当前对象
        this->y = y;
    }

    void point::move(int dx, int dy) {
        x += dx;
        y += dy;
    }

    void point::print() const {
        std::cout << "Point(" << x << ", " << y << ")" << std::endl;
    }

    int main() {
        point a;
        a.init(1, 2);  // 初始坐标为 (1, 2)
        a.move(3, 4);  // 移动后坐标变为 (4, 6)
        a.print();     // 输出: Point(4, 6)
        return 0;
    }
    ```

!!! warning "Warning"
    在 C 语言中，使用类似的函数必须传入**结构体的指针**；而在 C++ 中，可以直接使用类中的函数。


1. **作用域解析运算符** `::`

- `#!cpp <Class Name>::<function name>`：调用类的函数
- `#!cpp ::<function name>`：调用**全局作用域**下的函数

2. **`#!cpp this`**：隐藏参数，是指向当前对象的指针（只能在非静态成员函数中使用）

```cpp
void point::print();
// 编译器中
void point::print(point* this);
```

3. **对象 = 属性 + 服务**

- 属性：类的成员变量（数据）
- 服务：类的成员函数（操作）
 
4. **类的声明与定义**
  
- 类的**声明**以及成员函数的原型，应当放在**头文件**中 `.h`
- 成员函数的**定义**应当放在**另一个源文件**中 `.cpp`

!!! tip "Tips"
    1. 每一个类的声明应放在**不同的头文件**中
    2. 每个头文件对应一个**具有相同文件名前缀**的源文件
    3. 头文件的内容应使用 `#!cpp #ifndef`、`#!cpp #define` 和 `#!cpp #endif` 进行包裹

## 构造函数

1. **类的构造函数**：用于初始化对象，在创建对象时**自动调用**

- **有参数的构造函数**
    
    ```cpp
    class point {
    public:
        point(int x, int y) {
            this->x = x;
            this->y = y;
        }
    };

    int main() {
        point a(1, 2);  // 调用构造函数初始化对象
        return 0;
    }
    ``` 

    !!! abstract "初始化列表"
        ```cpp
        class point {
            int x, y;
        public:
            point(int value) : y(value), x(y) {} 
        }
        ```

        1. 初始化顺序是**按照声明顺序进行的**，而非列表中的顺序
        2. **实例中 `x` 将会赋值成乱码**，`y` 赋值成 `value`

- **默认构造函数**：无参数的构造函数，默认调用

    ```cpp
    class point {
    public:
        point() {
            this->x = 0;
            this->y = 0;
        }
    };

    int main() {
        point a;  // 调用默认构造函数初始化对象
        return 0;
    }
    ```

!!! tip "Tips"
    1. 这两个构造函数可以**同时存在**（函数重载）
    2. 构造函数的名称需要**与类同名**；而初始化函数的名称可以是任意的
    3. 构造函数**没有返回类型**，而初始化函数**有返回类型** `void` 
 
2. **自动默认构造函数**：当你定义一个类且没有编写任何构造函数时，**编译器会自动**为你生成一个默认构造函数

!!! warning "Warning"
    1. 自动生成的构造函数不负责**基本类型**（`int`, `float`, 指针等）的初始化，它们的值是**随机的**
    2. 对于内置类，会调用其默认构造函数 **e.g.** `#!cpp std::string`

3. **类的析构函数**：用于销毁对象，在销毁对象时**自动调用**

```cpp
class point {
public:
    ~point() {
        std::cout << "Destructor called" << std::endl;
    }
};
```

- 在**程序运行结束**时，会自动调用析构函数，释放内存
- 析构函数执行的顺序是**构造函数的逆序**

## 重载函数

1. **重载函数**：在同一个类中定义多个名称相同但参数列表不同的函数

2. **参数列表不同**：通过参数的数量、类型或顺序来区分不同的构造函数

### **代理构造函数**

```cpp
class Info {
public:
    Info() { InitRest(); }             // 目标构造函数 (target)
    Info(int i) : Info() { type = i; } // 委托构造函数 (delegating)
    Info(char e) : Info() { name = e; }
};
```
 
1. **前提**：多个版本的重载构造函数在内部需要执行**相同的操作**
2. **目标构造函数**：真正执行初始化列表的构造函数
3. **代理构造函数**：调用目标构造函数的构造函数
4. **优点**：可以减少重载构造函数中的**代码重复**

5. **用法**：将对另一个构造函数的调用放在**初始化列表**中


!!! warning "Warning"
    但代理构造函数不能在其自身的初始化列表中初始化其他成员
    
    ```cpp
    class Info {
        Info() { InitRest(); }
        Info(int i) : Info(), type(i) {} // Error: 委托构造函数不能有初始化列表
    }
    ```

    **解决方案**：可以使用**私有**构造函数来为其他成员提供初始化

    ```cpp
    class Info {
    public:
        Info() : Info(1, 'a') {}          // 委托
        Info(int i) : Info(i, 'a') {}     // 委托
        Info(char e) : Info(1, e) {}
    private:
        Info(int i, char e) : type(i), name(e) {} // 目标
    };
    ```

5. **执行顺序**

- 目标构造函数的**初始化列表**
- 目标构造函数的函数体 `{}`
- 代理构造函数的函数体 `{}`

6. 可以创建一个**代理构造函数链**

```cpp
class Info {
public:
    Info() : Info(1) {}               // 1: 委托 （使用 2）
    Info(int i) : Info(i, 'a') {}     // 2: 既是目标也是委托 （使用 4）
    Info(char e) : Info(1, e) {}      // 3: 委托
private:
    Info(int i, char e) : type(i), name(e) {} // 4: 目标
};
```

!!! warning "Warning"
    但应防止出现**环状委托链**！！！

## 默认参数

1. **默认参数**：在函数**声明或定义**时为某些参数指定默认值，如果在函数调用时没有提供该参数的值，编译器会自动插入该值

2. **注意事项**：

- 默认参数必须**从右往左**设置，不能跳过某个参数 **e.g.** `#!cpp void print(int a = 1, int b)`
- 默认参数通常**只在函数声明中指定一次**，不要在定义中重复指定
- **默认参数与重载的冲突**：当默认参数遇到函数重载时，容易产生二义性错误

    ```C++
    void print(int x);
    void print(int x, int y = 10);
    // 调用
    print(5); // 编译器崩溃：不知道该调哪一个
    ```

3. **带默认参数的构造函数**：所有参数都有默认值的构造函数就是一个**默认构造函数**

## `#!cpp inline`
### 内联函数

!!! warning "Warning"
    调用函数的开销比较大

1. **内联函数**：在调用处就地展开，类似于**预处理器宏**，从而消除了函数调用的开销

```cpp
inline int add(int a, int b) {
    return a + b;
}
int main() {
    int c = add(1, 2);  // 展开成 c = 1 + 2 
}
```

2. **定义与声明**

- 在声明和定义处都要**重复使用** `#!cpp inline` 关键字
- 内联函数的定义可能不会在 **`.obj`** 文件中生成任何代码
- 必须将内联函数的完整定义放在**头文件**中，在需要该函数的地方使用 `#!cpp #include`

!!! tip "优势与劣势"
    1. 不用担心内联函数的**多重定义**问题，内联函数的定义**仅仅是声明**
    2. **权衡**：可能会增加代码体积，但减少了调用的时间开销，因此内联函数是**以空间换取速度**
    3. 相比于 C 语言中的宏，会进行**参数类型检查**（安全）

!!! warning "Warning" 
    内联函数**可能不会被内联**，编译器**并不一定**要满足将函数设为内联的请求：
    
    - 可能会判定函数体**过大**
    - 或者发现函数**调用了自身**（内联函数不允许也不可能实现递归）
    - 或者特定编译器可能未实现该特性

3. **内联函数与类**：如果将函数的完整定义写在类的声明中，则该函数默认是**内联函数**（不需要加关键字）

### 内联变量

!!! warning "为什么要引入内联变量"
    === "header.h"
        ```cpp
        #ifndef HEADER_H
        #define HEADER_H

        const int globalValue = 42; // 定义全局变量

        #endif
        ```

    === "file1.cpp"
        ```cpp
        #include "header.h"     
        ```
    
    === "file2.cpp"
        ```cpp
        #include "header.h"
        ```

    如果在**头文件中定义变量**，因为每个包含该头文件的文件都会生成该变量的一个独立副本，这通常会导致链接阶段出现**多重定义错误**

    !!! success "解决方法"
        为了避免这种情况，变量通常在头文件中使用 `extern` 声明，并在单个 `.cpp` 文件中定义
        
        **但是这种方法虽然可行，但需要将声明和定义分开，这并不总是很方便**
    
1. **`#!cpp inline` 变量**：通过使用 `#!cpp inline` 变量，可以**直接在头文件中定义变量**，而不会导致链接错误

```cpp
#ifndef HEADER_H
#define HEADER_H

inline const int globalValue = 42; // 定义全局变量

#endif
```

2. `#!cpp inline` 变量的**核心特性**

- 跨编译单元的**单一定义**：编译器确保即使变量被包含在多个文件中，`#!cpp inline` 变量也只存在一个实例
- **在头文件中初始化**：可以在头文件中同时声明和初始化变量，使代码更加简洁
- 全局或静态变量：非常适用于**全局常量、类的静态成员**或单例模式

3. **`#!cpp inline static`** 允许直接在类中**定义并初始化**静态成员变量，无需在 `.cpp` 文件中进行单独定义

```cpp
class Config {
public:
    inline static int maxConnections = 100;
    inline static std::string appName = "MyApp";
};
```

!!! info "使用场景"
    1. 何时使用 `#!cpp inline` 变量
    
    - 在头文件中定义**全局常量**时
    - 使用直接**在类定义中初始化的静态类成员**时
    - 当需要在多个文件中共享变量的**单一定义**时
    - 当需要简化配置值或设置的管理时

    2. 何时不使用 `#!cpp inline` 变量
    
    - 避免对**大型对象或消耗大量内存**的变量使用 `#!cpp inline` 变量，可能会导致不必要的内存占用
    - 不要对需要在每个编译单元中拥有**独立实例的变量**使用 `#!cpp inline`
    - 对**运行时可能被修改**的变量使用 `#!cpp inline` 时要谨慎，因为可能会导致意想不到的副作用

## `#!cpp weak`

```cpp
// 作为一个备选项的弱函数定义
__attribute__((weak)) void printMessage() {
    std::cout << "Default message" << std::endl;
}
```

|  | `#!cpp inline` | `#!cpp weak` |
| :--- | :--- | :--- |
| **主要目的** | 通过向编译器建议内联来优化函数调用，**提高性能** | **允许符号覆盖并防止链接冲突** |
| **适用范围** | 主要用于函数（尤其是小型或频繁调用的函数） | 用于函数、变量或对象（尤其是在动态链接或插件系统中） |
| **符号管理** | 编译器可能会在不同编译单元中生成多个函数副本，并进行**去重** | **多个弱符号可以共存**，链接器会选择最强的一个（非 `#!cpp weak` 符号，如果存在的话） |

## 访问控制

1. **通过三个关键字来限制类成员的可见性**

- `#!cpp public`：任何地方都可以访问
- `#!cpp private`：只能在类的内部访问（同一个类的不同对象可以访问），派生类无法访问
- `#!cpp protected`：派生类和类的内部可以访问

!!! abstract "struct & class"
    `#!cpp class` 的默认访问权限是 `#!cpp private`

    `#!cpp struct` 的默认访问权限是 `#!cpp public`

2. **友元**：一种明确授予**非结构成员函数**访问权限的方法

- **类本身**控制哪些代码可以访问其成员
- 可以将全局函数、另一个类的成员函数、甚至整个类声明为友元
- **特点**：非对称性、非传递性、不可继承性（友元无法访问派生类）

```cpp
class point {
public:
    // 友元函数声明
    friend void print_point(const point& p);
    friend void Y::print_point(const point& p);
}
```

## 不同位置的对象

1. **局部对象**

- 定义在方法内部，其作用域仅限于所属的方法
- **生命周期**：函数执行期间
- **存储位置**：栈
- **与成员变量同名**的局部变量会阻止在方法内访问该成员变量（字段）

2. **全局变量**

```cpp
#include "X.h"
X global_x(12, 34);
X global_x2(8, 16);
```

- **存储位置**：全局/静态存储区
- **构造函数**在进入 `main()` 之前被调用（`main()` 不再是第一个被调用的函数）
- **析构函数**在以下情况被调用：
    - `main()` 退出时
    - 或者调用 `exit()` 时


3. **静态初始化依赖**

- 文件内部的构造顺序是确定的，不同文件之间的顺序是**未定义的**
- **非局部静态对象**：
    - 定义在全局或命名空间作用域的对象
    - 在类中声明为 `static` 的成员
    - 在文件作用域内定义为 `static` 的对象

!!! warning "Warning"
    当不同文件中的非局部静态对象存在**依赖关系**时，**会出现问题**

    !!! success "解决方案"
        1. 避免非局部静态依赖
        2. 将静态对象定义放在**单个文件**中，并按正确的顺序排列

## static

1. **都**存储在全局/静态存储区中

2. **两个基本含义**：

- **静态存储**：只进行一次初始化，地址固定
- **访问限制**：内部链接，只在定义他们的文件内可见

3. **静态成员**：属于类本身，而不属于**类**的任何特定对象

- **静态成员变量**：
    - 由该类的所有对象共享
    - 必须**在类外定义**和初始化
    - 也满足访问控制的规则
    - 可以不通过对象直接调用 `point::x`
    - 实际上是全局变量，`sizeof(object)` 不包含静态成员变量的大小
- **静态成员函数**：
    - **没有 `this` 指针**，不能访问**非静态成员**
    - 可以不通过对象直接调用 `point::print()`

!!! warning "Warning"
    在 C++ 中不建议使用 `static`，除非是在函数或类内部

4. **作用域与生命周期**

|变量类型|作用域|生命周期|初始化时间|
|:--|:--|:--|:--|
|**局部变量**|`{}` 内部|`{}` 内部|执行到定义行时|
|**全局变量**|全局|全局|在定义行，于 `main()` 之前|
|**静态局部变量**|`{}` 内部|全局|第一次执行到该行时|
|**静态全局变量**|文件内|全局|在定义行，于 `main()` 之前|
|**成员变量**|类内部|随对象的生命周期|创建该对象时|
|**静态成员变量**|类内部|全局|在定义行，于 `main()` 之前|

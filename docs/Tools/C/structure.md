## 头文件 
**标准头文件结构**

1. **作用**：运⽤**条件编译和宏**，保证这个头⽂件在⼀个编译单元中只会被`#include`⼀次
2. 任何`.c`都有对应的同名的`.h`文件，把所有对外公开的函数的原型和全局变量的声明都放进去

!!! tip "Tips"
    **不对外公开的函数**：在函数前⾯加上 `static` 就使得它成为只能在所在的编译单元中被使⽤的函数


```c
// main.h
#ifndef Main_H
#define Main_H
#include <stdio.h>
#include "node.h"    //文本插入

typedef struct list{
    Node *head;
    Node *tail;
} List;

#endif
```

!!! abstract "Note"
    `#pragma once`也可以起到相同的保护作⽤，但是不是所有的编译器都⽀持。

??? abstract """与<>的区别"
    1. `""`：先在当前目录中寻找，找不到再跳到指定目录
    2. `<>`：只在编译器指定的目录中寻找
    
## 宏
### 书写规则
1. 如果一个宏的值**超过一行**，最后一行之前的行末需要加 `\`
2. 宏的值后⾯出现的**注释**不会被当作宏的值的⼀部分
3. `#`开头的编辑预处理指令不是C语言的语句，**没有结尾的分号**
4. `#define cube(x) ((x)*(x))`

!!! bug "错误定义的宏"
    ```c
    #define RADTODEG(x) (x * 57.29578)
    #define RADTODEG(x) (x) * 57.29578
    ```

5. `#define PRINT_INT(n) printf(#n "=%d" , n)`：相当于`printf(“n””=%d”,n)`

!!! abstract "#与##运算符"
    1. `#n` 是字符串化运算符，将参数 `n` 转换为字符串常量。
    2. `##`：相当于紧挨着
        ```c
        #define CONCAT(a,b) a##b    //表示ab
        ```

6. `#error "my bad"`

### 预定义的宏
1. `__LINE__`：表示所处的行号
2. `__FILE__`：文件名
3. `__DATE__`：编译时的日期
4. `__TIME__`：编译时的时间
5. `__STDC__`：如果编译器遵循`ANSI C`，则其值为`1`，否则未定义

## 变量的储存类型
### 存储类型
1. **静态存储**：

- **变量类型**：静态变量
- **特点**：在程序**编译**时就已经分配好内存空间，该变量一直占有**固有**的内存空间，**程序结束后**才释放该部分内存空间

2. **动态存储**：

- **变量类型**：局部变量
- **特点**：在程序运行过程中，只有当**变量所在的函数被调用时**，该变量才会被分配内存空间，当**被调函数调用结束**时，该变量内存空间就会被释放，值就会消失
- 动态存储区：堆
### 变量声明类型
1. **自动变量声明** `auto`

- **函数中的局部变量**如果不用`static`声明，默认为自动变量
- **存储位置：**存储存在动态区

2. **静态变量声明** `static`

- **存储位置：**储存在静态区
- **分类**
    - **静态局部变量**：在调用到该函数时分配内存空间，但是当函数调用结束后**并不会释放该变量内存空间**，而是保存起来，下一次调用**还是上一次的值**
    - **静态全局变量**：**只能在本源文件调用**，不能被其他源文件调用（一个程序一般由多个源文件组成）

3. **寄存器变量声明** `register`

- **存储空间**：**动态分配**，调用结束后便**释放空间**
- **目的**：建议编译器将该变量存储在`CPU`的**寄存器**中，而不是像普通变量那样存储在内存里
- 寄存器的访问速度比内存的访问速度**快**，若某变量需要**频繁访问**，就可以定义为寄存器变量，将大大提高程序的执行效率

4. **外部变量声明** `extern`

- **适用场景：**在另一个源文件中想要使用该变量就可以用`extern`声明（前提是该变量不是静态变量）
- **e.g.** 如果文件`a.c`需要引用`b.c`中变量`int v`，就可以在` a.c`中声明`extern int v`，然后就可以引用变量`v`


### 总结
| 变量类型       | 存储区   | 函数结束变量的值 | 未初始化的变量的值 | 作用域         |
|:--:|:--:|:--:|:--:|:--:|
| 自动局部变量   | 动态区   | 消失             | 不确定             | 本函数         |
| 静态局部变量   | 静态区   | 保存             | 0                  | 本函数         |
| 静态全局变量   | 静态区   | 保存             | 0                  | 本文件         |
| 非静态全局变量 | 静态区   | 保存             | 0                  | 整个程序       |
| 寄存器变量     | 寄存器   | 保存             | 不确定             | 本函数         |



!!! abstract "全局变量"
    1. **分类**

    - **静态全局变量**： **仅限于定义它的源文件**，其他源文件不能直接访问这个静态全局变量（有助于避免不同源文件中的同名变量相互干扰，提高了程序的模块化性）
    - **普通全局变量**： 整个程序一旦定义了一个全局变量，在**同一个程序的所有源文件**中，只要经过适当的声明`extern`，就可以访问这个全局变量

    2. **生命周期**：**都是整个程序的运行期间**（在程序开始运行时分配内存空间，在程序结束时释放内存，即使在函数调用过程中，它所占用的内存空间也不会被释放）



!!! abstract "变量的声明和定义"
    1. **声明**：不分配内存
    2. **定义**：分配内存
    
    **Notice**：

    1. 同一个编译单元里，同名的结构不能被重复声明
    2. 所有的定义都是声明，但并非所有的声明都是定义

    ```c
    extern int global_var;  // 声明(不分配内存)
    int global_var = 100;   // 定义(分配内存)
    void func(void);        // 函数声明
    void func(void) {       // 函数定义
        // 函数体
    }
    ```

## 程序运行

1. **预处理**：预处理器根据`#`开头的命令修改源程序，得到`hello.i`（处理宏）
2. **编译阶段**：将`hello.i`翻译成**汇编语言**程序`hello.s`
3. **汇编阶段**：将`hello.s`翻译为**机器语言**指令，并打包为一种叫可重定位目标程序的格式，结果保存在`hello.o`文件
4. **链接阶段**：将编译后形成的一组目标模块，以及所需库函数链接在一起，形成一个完整的装入模块`hello`，它是一个**可执行目标文件**

??? abstract "链接方式"
    1. **静态链接:** 在程序运行之前，先将各目标模块及它们所需的库函数连接成一个完整的可执行文件(装入模块)之后不再拆开，要运行时可直接将它装入内存。
    2. **装入时动态链接**:将各目标模块装入内存时，边装入边链接
    3. **运行时动态链接**:在程序执行中需要该目标模块时，才对它进行链接（便于修改和更新,便于实现对目标模块的共享）

!!! tip "Tips"
    **编译阶段**会针对静态变量、全局变量等做好内存分配的前期规划

    **链接阶段**会对这些规划做进一步整合完善以便后续正确分配内存


## Makefile

!!! info "Makefile 详细知识"
    参照文档 [Makefile](https://seisman.github.io/how-to-write-makefile/)

```makefile
CC = gcc              # C编译器            
SRC = src             # 源文件目录           
CFLAG = -I $(SRC)     # 头文件目录           
OBJS = main.o $(SRC)/linkedlist.o  # 目标文件列表
test: $(OBJS)        # gcc -I src main.o src/linkedlist.o -o test
	$(CC) $(CFLAG) $(OBJS) -o $@  
%.o: %.c            # gcc -I src -c src/linkedlist.c -o src/linkedlist.o
	$(CC) $(CFLAG) -c $< -o $@  
clean:                # 清理命令
	rm -f $(OBJS) test
```

1. `Makefile`**变量**：

- `$^`: 表示上面的所有被依赖文件
- `$<`: 表示第一个依赖文件
- `$@`: 表示上边被依赖文件的目标

2. `@ echo $^`: 表示输出上边所有被依赖文件

    `@`后边的`echo`不会被打出来，但是如果没有`@`就会被打出来

3. 代码 `.o.c` 等价于 `%.o : %.c`


## 程序内存
|程序在内存中的分布|储存数据|
|:--:|:--:|
|内核空间 kernel||
|栈 stack|函数、形参、局部变量等|
|共享数据||
|堆 heap|动态开辟空间|
|未初始化数据段 .bss|未初始化全局变量|
|初始化数据段 .data|已初始化全局变量|
|只读数据段 .rodata|常量|
|代码段 .text|程序代码指令|
|保留区||


1. **栈（Stack）**

- **储存数据**：局部变量和函数调用的上下文信息（如参数和返回地址）
- **内存分配**：栈内存的申请和释放是由**编译器**自动管理的，通常在函数调用时分配，在函数返回时释放
- **常见问题**：栈的大小通常有限，**过深的递归或大型局部变量**可能导致**栈溢出**

2. **堆（Heap）**

- **用途**：用于动态内存分配的内存区域
- **内存分配**：可以通过`malloc`、`free`等函数显式地分配和释放内存
- **常见问题**：
    - 堆内存的管理更加灵活，但也更容易出错，如**内存泄漏和野指针**问题
    - 堆的大小通常比栈大得多，但也需要程序员合理管理，以避免**内存碎片**等问题

3. **全局/静态存储区**

- **储存数据**：用于存放全局变量和静态变量（在程序的整个运行期间都存在）
- **内存分配**：在**编译**时分配内存，通常位于**数据段（已初始化）或BSS段（未初始化）**。

4. **常量存储区**：用于存放程序中的常量数据，这些数据在程序运行期间**不可修改**
5. **代码段**：包含程序的**执行代码**，这部分内存是**只读的**，用于存储代码指令

    #include <iostream>

class point {
public:
    // 成员函数声明
    void init(int x, int y);
    void move(int dx, int dy);
    void print() const; 

private:        // 外部无法访问
    int x, y;
};

// --- 成员函数的实现 ---

void point::init(int x, int y) {
    this->x = x;        // this 指向当前对象
    this->y = y;
}

void point::move(int dx, int dy) {
    x += dx;
    y += dy;
}

void point::print() const {
    std::cout << "Point(" << x << ", " << y << ")" << std::endl;
}

int main() {
    point a;
    a.init(1, 2);  // 初始坐标为 (1, 2)
    a.move(3, 4);  // 移动后坐标变为 (4, 6)
    a.print();     // 输出: Point(4, 6)
    return 0;
}

    Warning

    在 C 语言中，使用类似的函数必须传入结构体的指针；而在 C++ 中，可以直接使用类中的函数。

    1. 作用域解析运算符 ::
    • <Class Name>::<function name>：调用类的函数
    • ::<function name>：调用全局作用域下的函数
    1. this：隐藏参数，是指向当前对象的指针（只能在非静态成员函数中使用）
    C++
    1
2
3
    void point::print();
// 编译器中
void point::print(point* this);
    1. 对象 = 属性 + 服务
    • 属性：类的成员变量（数据）
    • 服务：类的成员函数（操作）
    1. 类的声明与定义
    • 类的声明以及成员函数的原型，应当放在头文件中 .h
    • 成员函数的定义应当放在另一个源文件中 .cpp

    Tips

    1. 每一个类的声明应放在不同的头文件中
    2. 每个头文件对应一个具有相同文件名前缀的源文件
    3. 头文件的内容应使用 #ifndef、#define 和 #endif 进行包裹

    1. 这两个构造函数可以同时存在（函数重载）
    2. 构造函数的名称需要与类同名；而初始化函数的名称可以是任意的
    3. 构造函数没有返回类型，而初始化函数有返回类型 void
    1. 自动默认构造函数：当你定义一个类且没有编写任何构造函数时，编译器会自动为你生成一个默认构造函数

    Warning

    1. 自动生成的构造函数不负责基本类型（int, float, 指针等）的初始化，它们的值是随机的
    2. 对于内置类，会调用其默认构造函数 e.g. std::string
    1. 类的析构函数：用于销毁对象，在销毁对象时自动调用

    重载函数¶

    1. 重载函数：在同一个类中定义多个名称相同但参数列表不同的函数

    2. 参数列表不同：通过参数的数量、类型或顺序来区分不同的构造函数

    代理构造函数¶

    C++
    1
2
3
4
5
6
    class Info {
public:
    Info() { InitRest(); }             // 目标构造函数 (target)
    Info(int i) : Info() { type = i; } // 委托构造函数 (delegating)
    Info(char e) : Info() { name = e; }
};
    1. 前提：多个版本的重载构造函数在内部需要执行相同的操作
    2. 目标构造函数：真正执行初始化列表的构造函数
    3. 代理构造函数：调用目标构造函数的构造函数

    4. 优点：可以减少重载构造函数中的代码重复

    5. 用法：将对另一个构造函数的调用放在初始化列表中

    Warning

    但代理构造函数不能在其自身的初始化列表中初始化其他成员

    C++
    1
2
3
4
    class Info {
    Info() { InitRest(); }
    Info(int i) : Info(), type(i) {} // Error: 委托构造函数不能有初始化列表
}

    解决方案：可以使用私有构造函数来为其他成员提供初始化

    C++
    1
2
3
4
5
6
7
8
    class Info {
public:
    Info() : Info(1, 'a') {}          // 委托
    Info(int i) : Info(i, 'a') {}     // 委托
    Info(char e) : Info(1, e) {}
private:
    Info(int i, char e) : type(i), name(e) {} // 目标
};
    1. 执行顺序
    • 目标构造函数的初始化列表
    • 目标构造函数的函数体 {}
    • 代理构造函数的函数体 {}
    1. 可以创建一个代理构造函数链
    C++
    1
2
3
4
5
6
7
8
    class Info {
public:
    Info() : Info(1) {}               // 1: 委托 （使用 2）
    Info(int i) : Info(i, 'a') {}     // 2: 既是目标也是委托 （使用 4）
    Info(char e) : Info(1, e) {}      // 3: 委托
private:
    Info(int i, char e) : type(i), name(e) {} // 4: 目标
};

    Warning

    但应防止出现环状委托链！！！

    默认参数¶

    1. 默认参数：在函数声明或定义时为某些参数指定默认值，如果在函数调用时没有提供该参数的值，编译器会自动插入该值

    2. 注意事项：

    • 默认参数必须从右往左设置，不能跳过某个参数 e.g. void print(int a = 1, int b)
    • 默认参数通常只在函数声明中指定一次，不要在定义中重复指定

    • 默认参数与重载的冲突：当默认参数遇到函数重载时，容易产生二义性错误

      C++
      1
2
3
4
      void print(int x);
void print(int x, int y = 10);
// 调用
print(5); // 编译器崩溃：不知道该调哪一个
    1. 带默认参数的构造函数：所有参数都有默认值的构造函数就是一个默认构造函数

    inline¶

    内联函数¶

    Warning

    调用函数的开销比较大

    1. 内联函数：在调用处就地展开，类似于预处理器宏，从而消除了函数调用的开销
    C++
    1
2
3
4
5
6
    inline int add(int a, int b) {
    return a + b;
}
int main() {
    int c = add(1, 2);  // 展开成 c = 1 + 2 
}
    1. 定义与声明
    • 在声明和定义处都要重复使用 inline 关键字
    • 内联函数的定义可能不会在 .obj 文件中生成任何代码
    • 必须将内联函数的完整定义放在头文件中，在需要该函数的地方使用 #include

    优势与劣势

    1. 不用担心内联函数的多重定义问题，内联函数的定义仅仅是声明
    2. 权衡：可能会增加代码体积，但减少了调用的时间开销，因此内联函数是以空间换取速度
    3. 相比于 C 语言中的宏，会进行参数类型检查（安全）

    Warning

    内联函数可能不会被内联，编译器并不一定要满足将函数设为内联的请求：

    • 可能会判定函数体过大
    • 或者发现函数调用了自身（内联函数不允许也不可能实现递归）
    • 或者特定编译器可能未实现该特性
    1. 内联函数与类：如果将函数的完整定义写在类的声明中，则该函数默认是内联函数（不需要加关键字）

    内联变量¶

    为什么要引入内联变量

    C++
    1
2
3
4
5
6
    #ifndef HEADER_H
#define HEADER_H

const int globalValue = 42; // 定义全局变量

#endif
    C++
    1
    #include "header.h"
    C++
    1
    #include "header.h"

    如果在头文件中定义变量，因为每个包含该头文件的文件都会生成该变量的一个独立副本，这通常会导致链接阶段出现多重定义错误

    解决方法

    为了避免这种情况，变量通常在头文件中使用 extern 声明，并在单个 .cpp 文件中定义

    但是这种方法虽然可行，但需要将声明和定义分开，这并不总是很方便

    1. inline 变量：通过使用 inline 变量，可以直接在头文件中定义变量，而不会导致链接错误
    C++
    1
2
3
4
5
6
    #ifndef HEADER_H
#define HEADER_H

inline const int globalValue = 42; // 定义全局变量

#endif
    1. inline 变量的核心特性
    • 跨编译单元的单一定义：编译器确保即使变量被包含在多个文件中，inline 变量也只存在一个实例
    • 在头文件中初始化：可以在头文件中同时声明和初始化变量，使代码更加简洁
    • 全局或静态变量：非常适用于全局常量、类的静态成员或单例模式
    1. inline static 允许直接在类中定义并初始化静态成员变量，无需在 .cpp 文件中进行单独定义
    C++
    1
2
3
4
5
    class Config {
public:
    inline static int maxConnections = 100;
    inline static std::string appName = "MyApp";
};

    使用场景

    1. 何时使用 inline 变量
    • 在头文件中定义全局常量时
    • 使用直接在类定义中初始化的静态类成员时
    • 当需要在多个文件中共享变量的单一定义时
    • 当需要简化配置值或设置的管理时
    1. 何时不使用 inline 变量
    • 避免对大型对象或消耗大量内存的变量使用 inline 变量，可能会导致不必要的内存占用
    • 不要对需要在每个编译单元中拥有独立实例的变量使用 inline
    • 对运行时可能被修改的变量使用 inline 时要谨慎，因为可能会导致意想不到的副作用

    weak¶

    C++
    1
2
3
4
    // 作为一个备选项的弱函数定义
__attribute__((weak)) void printMessage() {
    std::cout << "Default message" << std::endl;
}
    inline weak
    主要目的 通过向编译器建议内联来优化函数调用，提高性能 允许符号覆盖并防止链接冲突
    适用范围 主要用于函数（尤其是小型或频繁调用的函数） 用于函数、变量或对象（尤其是在动态链接或插件系统中）
    符号管理 编译器可能会在不同编译单元中生成多个函数副本，并进行去重 多个弱符号可以共存，链接器会选择最强的一个（非 weak 符号，如果存在的话）

    访问控制¶

    1. 通过三个关键字来限制类成员的可见性
    • public：任何地方都可以访问
    • private：只能在类的内部访问（同一个类的不同对象可以访问），派生类无法访问
    • protected：派生类和类的内部可以访问

    struct & class

    class 的默认访问权限是 private

    struct 的默认访问权限是 public

    1. 友元：一种明确授予非结构成员函数访问权限的方法
    • 类本身控制哪些代码可以访问其成员
    • 可以将全局函数、另一个类的成员函数、甚至整个类声明为友元
    • 特点：非对称性、非传递性、不可继承性（友元无法访问派生类）
    C++
    1
2
3
4
5
6
    class point {
public:
    // 友元函数声明
    friend void print_point(const point& p);
    friend void Y::print_point(const point& p);
}

    不同位置的对象¶

    1. 局部对象
    • 定义在方法内部，其作用域仅限于所属的方法
    • 生命周期：函数执行期间
    • 存储位置：栈
    • 与成员变量同名的局部变量会阻止在方法内访问该成员变量（字段）
    1. 全局变量
    C++
    1
2
3
    #include "X.h"
X global_x(12, 34);
X global_x2(8, 16);
    • 存储位置：全局/静态存储区
    • 构造函数在进入 main() 之前被调用（main() 不再是第一个被调用的函数）
    • 析构函数在以下情况被调用：
      • main() 退出时
      • 或者调用 exit() 时
    1. 静态初始化依赖
    • 文件内部的构造顺序是确定的，不同文件之间的顺序是未定义的
    • 非局部静态对象：
      • 定义在全局或命名空间作用域的对象
      • 在类中声明为 static 的成员
      • 在文件作用域内定义为 static 的对象

    Warning

    当不同文件中的非局部静态对象存在依赖关系时，会出现问题

    解决方案

    1. 避免非局部静态依赖
    2. 将静态对象定义放在单个文件中，并按正确的顺序排列

    static¶

    1. 都存储在全局/静态存储区中

    2. 两个基本含义：

    • 静态存储：只进行一次初始化，地址固定
    • 访问限制：内部链接，只在定义他们的文件内可见
    1. 静态成员：属于类本身，而不属于类的任何特定对象
    • 静态成员变量：
      • 由该类的所有对象共享
      • 必须在类外定义和初始化
      • 也满足访问控制的规则
      • 可以不通过对象直接调用 point::x
      • 实际上是全局变量，sizeof(object) 不包含静态成员变量的大小
    • 静态成员函数：
      • 没有 this 指针，不能访问非静态成员
      • 可以不通过对象直接调用 point::print()

    Warning

    在 C++ 中不建议使用 static，除非是在函数或类内部

    1. 作用域与生命周期
    变量类型 作用域 生命周期 初始化时间
    局部变量 {} 内部 {} 内部 执行到定义行时
    全局变量 全局 全局 在定义行，于 main() 之前
    静态局部变量 {} 内部 全局 第一次执行到该行时
    静态全局变量 文件内 全局 在定义行，于 main() 之前
    成员变量 类内部 随对象的生命周期 创建该对象时
    静态成员变量 类内部 全局 在定义行，于 main() 之前
